# 编辑、执行与写作规范

仅在修改仓库文件时读取本文件。

## 1. 文件编辑与 Windows 执行

- 源代码、Markdown、YAML、JSON、CSV 和其他文本统一使用 UTF-8。
- 优先使用环境提供的结构化补丁工具；脚本化文本处理使用 Python `pathlib` 并显式指定 `encoding="utf-8"`。
- 不使用 `cmd.exe echo`、shell 重定向、PowerShell 管道、ANSI 代码页或 Base64 传递和写入非 ASCII 文本。
- 将大型修改拆成可独立核验的补丁；不要为了应用补丁切换多个 shell 重复同一操作。
- 单条简单文件系统命令运行超过 30 秒时，停止并诊断运行器。
- 每完成一组修改，运行定向 `git diff --check`；随后按 UTF-8 回读修改文件，检查意外的 ASCII 问号 `?` 和 Unicode replacement character `U+FFFD`。
- 当前工作区文件是内容事实源。先读取目标文件的相关部分，再用 `git status --short -- <path>` 判断是否存在未提交改动；文件干净时无需读取历史 diff，文件非干净且任务可能重叠时才检查相关 diff 片段。
- 不得为了制造干净基线而自行提交、暂存或清理用户改动；不得执行 `git reset --hard`、`git checkout --` 等破坏性操作。
- checkpoint 只在完整任务验证通过、研究者明确确认交付并允许创建后生成；使用只包含本任务相关修改的语义完整 Git commit，不得夹带工作区中的其他改动。

## 2. 文档写作

- 禁止使用比喻、拟人和含义不确定的修辞。
- 不跳过推导、实验或判定步骤；首次出现的缩写、符号和指标必须定义。
- 明确区分事实、假设、推断和待验证解释，并记录负结果。
- 比较必须说明基线、方向、单位、样本数和不确定性。
- 仓库文档使用仓库相对路径；数学符号以 `DESIGN.md` 为准，新增符号先加入符号表。
- 仓库 Markdown 的行内公式使用 `$...$`，块级公式使用独占行的 `$$...$$`；不使用 `\(...\)` 或 `\[...\]`。
- 上一条不约束聊天窗口；聊天公式应使用客户端可正确渲染的格式。

## 3. 输出节制

- 搜索文件优先使用 `rg --files`，搜索内容优先使用 `rg`。
- 命令先限制路径、模式和输出行数。大日志先给错误摘要与命中位置，再按需展开上下文。
- 修改后的 Git 检查使用定向 `diff --check`、`diff --stat` 或相关变更片段；不同时输出完整最终文件和完整 diff，也不输出无关文件的差异。
- 不同时加载内容等价的图文版 result；默认读取无图版，视觉核验时再读对应图片。
- 不在多个 Agent 之间重复分配同一文件或同一材料的阅读任务。
