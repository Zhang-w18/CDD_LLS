# 实验结果与全局记录规范

仅在分析正式实验、编写 result 或更新 `GOALS.md`/`KNOWLEDGE.md` 时读取本文件。

## 1. 成对 result

每轮正式实验必须同时生成：

- `research/result-NNN-任务缩略词.md`：给研究者阅读，可以嵌入图；
- `research/result-NNN-任务缩略词-text.md`：禁止嵌入图片，仅靠文字、表格和原始数据引用即可独立核验。

其中 `任务缩略词` 必须与同轮 `research/plan-NNN-任务缩略词.md` 完全一致，并概括该轮主要任务；不得只使用 `result-NNN.md` 或 `result-NNN-text.md`。例如，`plan-034-RSRP统计-PDCCH 4T4R.md` 对应 `result-034-RSRP统计-PDCCH 4T4R.md` 与 `result-034-RSRP统计-PDCCH 4T4R-text.md`。

两版必须给出相同的结论、配置、关键数字、异常、验收判定和证据路径。每版至少包含：

1. **仿真条件**：完整参数及其含义、取值和单位，以及展开配置、代码版本或变更标识、种子、样本量和复现命令；
2. **实验结果原始数据**：支撑结论的关键原始数值或采样表，以及完整输出的精确路径、字段和单位；不得只给图或汇总结论；
3. **仿真结果分析**：逐项回答 plan 验收标准；检查结果在趋势、数量级、边界条件、不同指标之间以及相对基线的关系上是否存在明显逻辑错误，并给出检查依据；说明结果是否符合预期、统计不确定性、样本充分性、异常和适用范围；解释仿真结果意味着什么结论、不能支持什么结论以及仍需验证的问题，并区分事实、推断、假设及待验证解释。发现明显逻辑错误时，不得据此形成物理结论，必须记录错误表现、可能原因和后续处理。

result 应精简且自包含，不必复制不会影响结论核验的全部原始数据。引用外部数据时给出仓库相对精确路径、内容说明、字段和单位。

## 2. 图与数据

- 所有仿真结果图必须在本地工作区内，由仓库中的可复现脚本直接读取已保存的本地原始数据生成；不得上传数据到云端绘图服务，也不得使用模型侧或云端图像生成能力代画。result 应记录绘图脚本、输入数据、输出路径以及配置或完整复现命令。
- 被 Markdown 引用的图放 `docs/figures/<topic-or-result>/`，其他图留在 `outputs/`。
- 每张图必须有对应的文字或表格数据；禁止用“见图可知”代替分析。
- 采样表应说明抽样规则，并覆盖有利、持平和不利条件。
- 大规模数组留在 `outputs/`；优先提供 UTF-8 的 CSV、TSV、JSON、Markdown 或日志供复核。
- 分析仿真结果或撰写 result 时，不得向模型传输或加载结果图片；应提供无图版 result、图对应的原始数据、绘图输入表、日志或本地脚本生成的数值摘要。图片只作为本地生成并交付给研究者的产物，不作为模型分析输入，以避免不必要的图像传输与上下文消耗。
- 新增或修改图后，通过本地脚本运行状态、输入数据校验、输出文件存在性、格式和尺寸等信息完成自动检查；需要研究者判断的视觉布局问题应明确列为人工核验项，不得为此把仿真结果图片传回模型。
- 对同一特定方案，同一份 result 中所有图必须复用同一组颜色、线型和 marker；即使图例在缩写名与 `candidate NN` 编号之间切换，也不得改变该物理方案的样式映射。样式映射应由一个共享配置生成并随结果保存，禁止各图独立按绘制顺序分配样式。
- 图必须以缩小后插入 PPT 仍可快速辨认为可读性目标。除非 result 明确记录版面限制及替代值，坐标轴标签、标题和图例字体不小于 16 pt，刻度字体不小于 14 pt，曲线线宽不小于 2.5 pt，marker 尺寸不小于 8 pt；图例不得遮挡关键曲线或置信区间。
- 交付前应在本地生成约 13 cm 宽的 PPT 半页尺寸预览文件，供研究者人工核对横纵坐标、标签、标题、图例、颜色、线型和 marker 是否均可辨认；模型不得加载该预览图。若曲线密集，应优先由本地绘图脚本调整画布、图例布局和采样 marker 间隔，不得通过缩小字体或线宽解决拥挤。

## 3. 可信性与异常

报告样本数、统计区间或其他不确定性度量，并说明样本不足时能够与不能够得出的结论。负结果、失败运行、后验发现的配置偏差和不可直接比较的条件都必须记录，不得只保留有利结果。

## 4. 更新 KNOWLEDGE 与 GOALS

result 经研究者确认后，才能把结论写入 `KNOWLEDGE.md` 的已验证部分，或改变 `GOALS.md` 的阶段验收状态。

`GOALS.md` 按研究问题记录目标、背景、关键进展、当前判断、阶段验收和下一步，并引用 plan/result，不重复大段原始数据。实验或代码修改造成跨实验影响时，记录：

- 变更内容及前后差异；
- 生效的实验编号或代码版本；
- 影响范围和受影响的历史比较；
- 已有结果需要重算、重解释还是标记为不可比；
- 支撑该变更的 result、设计文档或代码路径。

物理量定义、单位、符号、归一化、基线、统计口径、接口或默认配置的变化属于全局变更。局部实现细节、完整原始数据和逐次日志留在 plan、result 或 `outputs/`。

## 5. 完成检查

核对同编号两版 result、展开配置、复现命令、原始证据、逐项验收、统计不确定性、异常、适用范围、引用图位置，以及 `research/README.md` 的索引。明确列出未完成或未确认的项目。
