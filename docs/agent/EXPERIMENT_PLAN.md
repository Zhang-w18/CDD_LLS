# 实验计划与执行规范

仅在制定或执行正式实验 plan 时读取本文件。理论问答、小型文档修改、只读诊断和范围明确的局部修复不要求创建 plan。

## 1. 制定前确认

制定 plan 前，与研究者确认本轮研究问题或交付目标，以及适用于本轮任务的候选与基线、公平性约束、量化判据、统计预算和停止条件。尚未确认的内容必须显式标记，整份 plan 标记为“草案”；不得代替研究者决定会实质改变研究问题、交付范围或公平性的条件。

## 2. plan 必需内容

每份 `research/plan-NNN-任务缩略词.md` 必须对本轮执行自包含，并包含：

1. 修改或实验目的：研究问题或明确的代码实现、仿真与分析交付目标，以及与 `GOALS.md`、`DESIGN.md` 的关系；
2. 修改或实验方法：总体方案、候选、基线、公平性约束、统计方法和判断思路；
3. 执行步骤或子任务：按依赖顺序列出代码、配置、测试、smoke、正式运行和结果整理；
4. 重要约束：系统模型、参数含义与取值、单位、索引和归一化约定、种子、trial、SNR 网格及预算；
5. 代码修改范围：预计修改的文件、接口或行为、兼容性和测试要求；无代码修改时明确说明；
6. 输出与复现：输出目录、文件、字段、单位、展开配置和复现命令；
7. 验收与停止条件：量化判据、统计不确定性、样本不足判定、停止条件和失败后的动作；
8. result 要求：两版 result 必须回答的问题和必须引用的证据。

不得为了满足模板而机械列出可证伪假设。对于主要任务是按既定要求编写代码、运行仿真和分析结果的 plan，应明确交付目标、验证方式、仿真配置、结果分析任务与验收条件；只有实验本身需要检验某项假设时，才记录该假设及其判定方式。

目的、关键方法、参数、约束和判据不得只写“同上一轮”或“见历史文档”；只有不影响本轮执行的背景材料可以引用。

## 3. 执行流程

1. 从 `research/README.md` 和实际文件核对未占用的 `NNN`。
2. 完成并确认 plan；缺少关键参数、判据、路径或复现入口时先补全，不得猜测。
3. 修改代码、配置和测试。稳定配置放 `configs/`，可复用算法放 `cdd_lls/`，专题入口放 `tools/`。
4. 运行测试或 smoke，核对单位、维度、索引、归一化、种子、输出字段和预期运行预算。
5. 正式产物写入 `outputs/<experiment_name>/<run_id>/`，并保存实际展开配置、日志和代码版本或变更标识。
6. 按 `docs/agent/RESULT_SPEC.md` 成对生成 `result-NNN-任务缩略词.md` 与 `result-NNN-任务缩略词-text.md`。
7. 研究者确认 result 后，按要求更新报告、`KNOWLEDGE.md`、`GOALS.md` 和 `research/README.md`。

## 4. 文档命名

- 新建 plan 必须命名为 `research/plan-NNN-任务缩略词.md`，不得只使用 `plan-NNN.md`。
- `任务缩略词` 必须从本轮主要任务提炼，简短、可辨识，并优先包含研究对象和关键场景，例如 `plan-034-RSRP统计-PDCCH 4T4R.md`。
- 同一轮 plan、图文 result 和无图 result 必须复用完全相同的 `NNN-任务缩略词`；不得为两版 result 另起缩略词。

不得以 smoke 结果替代正式结果，不得用后验调整的判据声称满足原 plan 验收条件。若执行中改变物理定义、基线、公平性或统计口径，应暂停正式比较，更新 plan 并说明历史结果是否仍可比较。
